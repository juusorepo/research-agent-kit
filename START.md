# Start here

**Status: early development / v0.x.** APIs, structures, and conventions are expected to change.

You do **not** need Python or R to begin.

## On your computer (one kit, many papers)

Keep **one** Research Agent Kit folder on your machine. Each paper is its **own** research folder.

```
Documents/
  research-agent-kit/     ← one copy; refresh this when GitHub changes
  wellbeing-gradients/    ← a paper
  another-study/          ← another paper
```

**Day to day, open only the paper.** Share kit + paper together only when starting a paper or updating the copied how-to files.

## First paper

Most papers start from an existing protocol or draft, not a blank page.

1. Open the **kit** folder. Say **Start the project**. Give your name.
2. The assistant creates a research folder next to the kit (`01-data`, `02-scripts`, `manuscript`, …).
3. **Copy** your plan, protocol, preregistration, or draft paper into that folder (`06-docs/` and `manuscript/`). Say when you have done that, or that there is nothing to copy.
4. Open the **paper** folder. Say **Understand the project**.

The assistant then says what it found. Copied files are source material: it can **draft** the overview and analysis plan from them; you **accept**; then it **writes** the files. You do not have to type them yourself.

Decision notes and the optional AI-use record start from now. Earlier work is not reconstructed. If a past choice still governs the paper, you can record that one decision as a new note.

The assistant then offers only this version’s next steps (not a literature search).

If you only send your name: folder **paper-1**, Quarto, R, numbered folders, no individual-level data, **no AI-use log**. Edit `policies/what-is-on.md` or say so if you want that log.

## What this version can do

| Always on | Optional | Not in this version |
|---|---|---|
| Overview, analysis plan, status, tasks | Record of material AI use (off unless you tick it) | Literature search |
| Data-use rules | | Journal disclosure forms |
| Collaborator inbox (`contributions/`) | | Word / Stata toolchains |
| No invented / unapproved numbers | | Automatic manuscript audit |
| Research decision notes for important choices | | |

**Skills** (ordinary verbs):

1. **Start the project** — folders, interview, copy-your-files check  
2. **Understand the project** — where things stand + what to do next (does not load working notes by default)  
3. **Specify / propose analyses**  
4. **Document a research decision**  
5. **Develop analysis with safe data**  
6. **Update the project record**  
7. **Work on the manuscript** — approved results only  
8. **Contribute / consolidate** — collaborator inbox; you decide what enters the record

## When GitHub is updated

Update the one kit folder, then in the paper say **Update the copied instructions from the kit.** Your overview, plan, data, scripts, and manuscript stay as they are.
